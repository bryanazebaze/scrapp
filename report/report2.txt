DIAGRAM 1 — LE MOTEUR DE SCRAPING (COMMENT ÇA COLLECTE)
================================================================================

Audience: non-technical. Shows what happens when the system visits a real-
estate website to collect property listings.

Layout: horizontal flow, left to right, 6 simple boxes with arrows between.

Step-by-step flow (left → right):

  [Site immobilier]          (e.g. mapiole.com — a real-estate website)
       │
       │  "Le robot visite le site"
       ▼
  [Page d'annonces]          (the page listing all properties for sale/rent)
       │
       │  "Le robot lit la page"
       ▼
  [Extraction]               (pulls out: title, price, location, photos, bedrooms, etc.)
       │                      "Il copie les informations de chaque bien"
       ▼
  [Nettoyage]                (fixes typos, standardizes prices to XAF,
       │                      detects city/neighborhood from raw text,
       │                      removes duplicates on the same site)
       │                      "Il corrige et uniformise les données"
       ▼
  [Comparaison]              (checks: is this property already in our database?
       │                      did the price change since last visit?)
       │                      "Il vérifie si le bien est déjà connu"
       ▼
  [Stockage]                 (saves to the central database:
                              new properties get added,
                              price changes get recorded in a history log)
                              "Il sauvegarde tout dans la base de données"

Key annotations (callout boxes below the flow):
  - "Le robot visite le site une fois par jour, automatiquement"
  - "Il respecte les règles du site (fichier robots.txt)"
  - "Il attend entre chaque page pour ne pas surcharger le site"
  - "Si le prix d'un bien change, l'ancien prix est conservé dans l'historique"

Visual suggestion:
  Use a "robot" icon or simple character at the [Extraction] step.
  Use a "database cylinder" icon at [Stockage].
  Color: orange for the robot steps, blue for storage.

DIAGRAM 5 — COMMENT LE SYSTÈME ÉVITE LES DOUBLONS
================================================================================

Audience: non-technical. Explains deduplication with a concrete example:
the same apartment listed on two different websites.

Layout: top section shows the problem (two sites, same property),
bottom section shows how the system merges them.

Top section — LE PROBLÈME:

  [Mapiole.com]                    [Kasastay.com]
   Annonce A:                        Annonce B:
   "Bel appartement 3 chambres"      "Appartement 3 ch Bastos"
   Bastos, Yaoundé                   Bastos, Yaoundé
   45 000 000 XAF                    47 500 000 XAF
   120 m²                            122 m²
   photos: [img1, img2]              photos: [img3, img4]

   "Deux annonces, mais c'est LE MÊME BIEN"

Middle section — LA COMPARAISON:

  [Le système compare:]
    ✓ Type: Appartement = Appartement          (pareil)
    ✓ Ville: Yaoundé = Yaoundé                  (pareil)
    ✓ Quartier: Bastos = Bastos                 (pareil)
    ~ Titre: "Bel appartement 3 chambres" ≈ "Appartement 3 ch Bastos"  (similaire à 85%)
    ~ Prix: 45M vs 47.5M — proche (écart 5%)
    ✓ Surface: 120 m² ≈ 122 m²                  (pareil, ±2 m²)
    ✓ Chambres: 3 = 3                            (pareil)

  [Score de confiance: 0.89 → Confirmé: c'est le même bien]

Bottom section — LE RÉSULTAT:

  [UNE SEULE ANNONCE CANONIQUE]
   "Bel appartement 3 chambres, Bastos Yaoundé"
   Meilleur prix: 45 000 000 XAF (Mapiole)
   Aussi disponible sur Kasastay: 47 500 000 XAF
   Sources: 2 plateformes
   L'utilisateur voit une seule annonce, pas deux.

Layout suggestion:
  Top: two boxes side by side with slightly different content.
  Middle: a "comparison" box with checkmarks (✓) and tildes (~).
  Bottom: one merged box with a "merged" icon.
  Use green checkmarks for matches, orange for similarities.
  The score (0.89) should be prominent — maybe in a badge.

Annotation:
  "Sans cette étape, l'utilisateur verrait le même bien deux fois.
   Le système reconnaît les doublons et n'affiche qu'une seule annonce,
   avec le meilleur prix parmi toutes les plateformes."

DIAGRAM 6 — LE SUIVI DES PRIX DANS LE TEMPS
================================================================================

Audience: non-technical. Shows how the system tracks price changes over
multiple crawls, building a price history.

Layout: timeline (horizontal), with crawl events as dots/boxes and a
price chart forming below.

Timeline:

  Jour 1 (1er mars):
    [Robot visite le site]
    → Trouve "Appartement Bastos, 50 000 000 XAF"
    → C'est nouveau → enregistre "première apparition"
    → Point sur le graphique: (1 mars, 50M)

  Jour 15 (15 mars):
    [Robot visite le site]
    → Trouve "Appartement Bastos, 45 000 000 XAF"
    → Le bien existe déjà (même URL)
    → Le prix a changé: 50M → 45M (baisse de 5M)
    → Enregistre "changement de prix"
    → Point sur le graphique: (15 mars, 45M)

  Jour 30 (30 mars):
    [Robot visite le site]
    → Trouve "Appartement Bastos, 45 000 000 XAF"
    → Le bien existe déjà
    → Le prix n'a pas changé (toujours 45M)
    → Aucune action (pas de nouvel événement)
    → Le graphique reste à 45M

  Jour 45 (15 avril):
    [Robot visite le site]
    → Le bien n'est plus sur le site!
    → Enregistre "retiré du marché"
    → Point sur le graphique: (15 avril, retiré)

Resulting price chart (shown below the timeline):

  Prix (XAF)
  50M ─●─
      │  ╲
      │   ╲
  45M │    ●────────●──── (retiré)
      │
      └──────────────────────────→ Temps
       1 mars  15 mars  30 mars  15 avril

Key points (callout):
  "Chaque fois que le robot visite le site, il compare le prix actuel
   avec le prix précédent. S'il a changé, il l'enregistre.
   L'utilisateur voit un graphique de l'évolution du prix."

  "L'ancien prix n'est JAMAIS effacé. Tout est conservé dans un historique
   qui ne fait que grandir."

Layout suggestion:
  Top: 4 crawl events as boxes with timestamps.
  Bottom: a simple line chart with points.
  Use a robot icon at each crawl event.
  Use a red "X" or "removed" icon at the last event.
  Green for price drops, red for price increases (or vice versa).

================================================================================

Audience: non-technical. Shows how a new real-estate website can be

Layout: horizontal flow with a decision gate and a review step.

Flow:

  1. [Administrateur]
       "J'ajoute un nouveau site: exemple-immo.cm"
       │
       ▼

  2. [Scraper universel — Étape 1: Découverte]
       "Le robot explore le site:
        - lit le plan du site (sitemap)

       │
       ▼

  3. [Scraper universel — Étape 2: Détection des cartes]

       "Le robot extrait les champs de chaque annonce:

        - priorité 2: OpenGraph (meta tags)
        - priorité 3: heuristiques (regex, CSS selectors)"
       │
       ▼

  5. [Scraper universel — Étape 4: Score de confiance]
       "Le système calcule un score de 0 à 1:
        - a-t-on trouvé des données structurées? (40%)
        - l'annonce vient-elle d'une carte détectée? (20%)
        - y a-t-il un prix? (15%)
        - les images sont-elles valides? (10%)
        - la ville est-elle reconnue? (10%)
        - le domaine est-il camerounais? (5%)"
       │
       ▼

  6. Decision gate (diamond):
       {Score de confiance?}
       │
       ├─ ≥ 0.75 → [AUTO-APPROUVÉ]
       │           "L'annonce est ajoutée automatiquement"
       │           "Elle apparaît sur l'application immédiatement"
       │
       ├─ 0.40–0.74 → [EN ATTENTE]
       │              "L'annonce est sauvegardée mais masquée"
       │              "Un humain doit la vérifier"
       │              ↓
       │           [Administrateur: file d'attente]
       │              "L'admin voit: titre, prix, lieu, photo, score"
       │              ↓
       │           Decision: {L'admin décide}
       │             ├─ Approuver → [APPROUVÉ] → apparaît sur l'app
       │             └─ Rejeter → [REJETÉ] → reste archivé, invisible
       │
       └─ < 0.40 → [REJETÉ]
                   "L'annonce n'est pas sauvegardée"
                   "Trop peu fiable pour être conservée"

Bottom annotation:
  "Ce système permet d'ajouter un nouveau site en quelques minutes,
   sans écrire de code. Les annonces les plus fiables sont ajoutées

  A "human review" sub-flow for the pending path.

DIAGRAM 10 — COMMENT LES IMAGES SONT GÉRÉES
================================================================================

Audience: non-technical. Explains why the system does NOT download/copy
images, but instead loads them directly from the original websites.

Layout: comparison — two approaches side by side.

LEFT SIDE (what the system does NOT do — shown with a red X):

  [Site immobilier]                 [Serveur CentralImmo]           [Application]
   photo du bien                     télécharge la photo             affiche la copie
       │                             │                              │
       └──→ [Téléchargement] ──→     [Stockage local 23MB]    ──→   [Photo copiée]
       "Copier l'image"               "Garder une copie"             "Afficher la copie"

  ❌ Problèmes:
     - 23 MB d'espace disque utilisé
     - Images qui deviennent obsolètes
     - Photos périmées si le site source les met à jour
     - Complexité de gestion (cache, nettoyage, chemins)
     - Risque de droits d'auteur (copie non autorisée)

RIGHT SIDE (what the system DOES — shown with a green checkmark):

  [Site immobilier]                                                [Application]
   photo du bien (URL: https://mapiole.com/img/123.jpg)
       │                                                           │
       └──────→ [URL stockée dans la base] ──────────────────→    [Charge l'image
                 "raw_listings.images_raw =                       directement depuis
                  ['https://mapiole.com/img/123.jpg',              le site d'origine"
                   'https://mapiole.com/img/124.jpg']"             (CachedNetworkImage)
       │                                                           │
       │  "On garde juste le LIEN, pas le fichier"                  │
       │                                                           ▼
       │                                              [L'utilisateur voit la photo
       │                                               en temps réel depuis le site]

  ✅ Avantages:
     - 0 MB d'espace disque (pas de téléchargement)
     - Toujours à jour (l'image change → l'app suit)
     - Pas de problème de droits d'auteur (on affiche, on copie pas)
     - Simplicité (pas de gestion de cache de fichiers)
     - Si l'image est supprimée du site → l'app affiche un placeholder

Bottom annotation:

  "Le système stocke uniquement les LIENS (URLs) vers les photos,
   pas les photos elles-mêmes. Quand l'utilisateur ouvre une annonce,
   l'application charge la photo directement depuis le site immobilier.

   C'est comme un favori dans votre navigateur: vous gardez le lien,
   pas une copie de la page web."

  "Si une photo n'est plus disponible sur le site d'origine,
   l'application affiche une image de remplacement (placeholder)
   au lieu d'une image cassée."

Layout suggestion:
  Two columns: left (red, "ancienne approche — copie"), right (green, "nouvelle approche — lien").
  Use a photo icon, a server icon, and a phone icon in each column.
  Red X over the left approach, green checkmark on the right.
  Show the URL string in a "code" style box.
  Use a "broken image" placeholder icon in the annotation about missing images.

Notes for the diagram generator:
  1. All labels in French. Keep sentences SHORT (10-15 words max per box).
  2. Use simple icons: robot, phone, database cylinder, magnifying glass,
     chart, calendar, person, checkmark, X mark, photo, cloud.

     - Green #4CAF50: success, approved, correct
     - Red #F44336: rejected, error, "don't do this"
     - Yellow #FFC107: pending, waiting
     - Blue #2196F3: API/server, data flow
     - Grey #9E9E9E: storage, background
  4. Use large, readable font sizes. These are for non-technical readers.
  5. Arrows should have short labels (2-5 words) on them when possible.
  6. Each diagram should fit on ONE page. Do not split across pages.
  7. Use rounded corners for all boxes.
  8. For decision points, use diamond shapes with clear Yes/No labels.
  9. Numbered steps should have circled numbers.
  10. Keep each diagram SIMPLE — better to have 5 clear boxes than 15 cluttered ones.
